# P2 连续掘进段与阶段划分报告

路线图第三步：建立连续掘进段及阶段划分。输入是[标准时序数据v1](标准时序数据v1数据卡.md)，处理按你确认的“按默认处理继续P2”进行：优先用机器自己的掘进状态，缺失处用信号推断；范围是可用于预测的5台机器（TBM5、TBM6、TBM8、TBM9、TBM10）。所有数字由[`analysis/p2_*.py`](../)从v1重新算出，输出在[`segments_v1/`](segments_v1/)。下文的“K1型”指TBM5、TBM6，“K2型”指TBM8、TBM9、TBM10，是P0发现的两族驱动常数（扭矩比0.369对0.325，转速比0.0027对0.061）及其配套的状态列。

**人工抽样验证这一步我替不了你。** 这里交出的是：分段数据、可以直接交给现场工程师的抽样验证包（98页图、答题表、评分脚本），以及我自己看了这98页之后做的自查。自查的发现已经写进规则（第七节），所以它不是独立验证，更不是人工验证。

## 结论先行

1. **得到15,169个连续掘进段，共3,945小时。** 5台机器共5,566,731行，其中1,027,720行（18.5%）落在段内，每一行都有段号、阶段码和运行状态，没有删行、插值或平滑。≥5分钟的**长段9,193个，占段时间的96.7%（3,814小时）**；60秒到5分钟的短段2,474个、不足60秒或没有一行同时有推力和推进的瞬时段3,502个，合计只占3.3%。
2. **分段规则**：机器自己的掘进状态为开；相邻读数间隔不超过60秒；状态为开而推力为0的连续时间不到120秒。第三条不在你确认的默认处理里，是看图后加的（Q10）。
3. **机器的掘进状态与信号基本一致，但两个方向不对称。** 推力、扭矩、转速、推进速度同时大于0的行，几乎全在状态为开的行里（TBM5、TBM6、TBM8为100%，TBM9、TBM10为99.98%，共102行例外）；反过来，状态为开的行里完全活动的只占90.9%（TBM5）、92.4%（TBM6）、99.7%（TBM8）、98.1%（TBM9）、98.7%（TBM10）。差额是起停时刀盘转而推力还没有或已经撤掉（K1型中位约30秒）、推力短暂掉零，以及推力撤掉几分钟而状态仍为开（K1型常见，TBM9也有）：最后一种被第三条规则切出段外，TBM5共15.4小时、TBM6 5.9小时、TBM9 5.4小时。
4. **段边缘要带着“是否被截断”走。** 读数缺口（数据洞）让一个掘进过程在60秒规则下被拆成几段：长段里有8.5%至少一侧边缘不是观察到的状态变化（TBM5 12.3%、TBM6 6.9%、TBM8 13.4%、TBM9 7.0%、TBM10 7.0%），瞬时段里约一半贴着洞。这些边缘在表里标为`censored`，不命名上升段或下降段。间隔限从60秒放宽到120秒，TBM5的段数从3,518降到2,805，被洞截断的边缘从1,521降到102，但长段时间只增加3.4%（703到728小时）。
5. **阶段：9,193个长段中9,008个（98.0%）找到稳定阶段。** 另有133个因有效行不足90%没有划（几乎都是v无效的文件），49个没有正的稳定水平（多是推力在而推进为0），3个读数太少。按时间计，上升段占10%到16%，稳定段占84%到90%；下降段在K1型（TBM5、TBM6）占2.1%，在K2型（TBM8、TBM9、TBM10）不到0.3%，因为K2的推力是在一两个读数内释放的。
6. **阶段边界是约定，不是测量。** 稳定水平的阈值换成更严（推力95%、推进90%），20%到27%的长段稳定起点移动超过60秒，90%分位移动140到178秒，上升段时间占比从10%到16%升到13%到20%；改成只看推力则24%到42%移动超过60秒，上升段占比降到6%到11%。平滑窗口、保持读数数、稳定水平取段的哪一部分这几项几乎不起作用（起点移动超过60秒的段不超过5%）。**使用阶段标签时应当把边界当作±1到3分钟的约定。**
7. **推进量旁证（只有两台机器能逐段对照）**：TBM5（刀盘里程，步长0.1米）879个长段的“速度积分÷里程增量”中位数1.008（四分位0.92到1.09），TBM8（导向盾首里程，步长0.1米）416个长段中位数1.032（0.99到1.08）；TBM6、TBM10的计数器步长1米，TBM9的导向盾首里程在2024年4到5月有两个相差14米的值交替出现（第六节），都不能逐段对照。
8. **我的自查（98个分层抽样的段，不是人工验证）**：能判断的起点68/70、终点67/68、上升段结束51/53、下降段开始53/53落在我认为的位置约1分钟以内；8个我判为“不是掘进”的样本推进速度都接近0，全部带`stalled`标记（4个是推力在的停滞，4个是起动前的读数或单个读数），长段里这类有110个、共20.2小时；毛病集中在三类（第七节）：先在较低水平稳定、后来整体抬高的段，前一半被标成上升段；K1型状态早于推力很久；段内2分钟左右的停滞。**这些比例是我按自己设定的标准对自己设计的规则打的分，会偏乐观。**
9. **验证**：72项检查通过（表与标签互相一致、标签与v1逐行对应、独立的游程重算得到同样的段、独立的窗口重算在每台机器300个抽样段上得到同样的稳定阶段）；合成数据自检29项通过，期间植入的情形全部落到对应的位置，三种篡改都被验证脚本发现；重建的段表和标签文件逐字节一致。

## 一、你确认的默认处理在P2里怎么落实

| 默认处理 | P2里的做法 |
| --- | --- |
| 优先用机器自己的掘进状态，缺失处用信号推断 | 逐行取`state_boring`；没有这一列的行（TBM5的2023年前半段，791,913行）取`state_thrust`等于3；两个状态都缺的2行（TBM5）取`active`。每个段记它主要依据的来源（`ref_source`） |
| 范围是5台可用机器 | 由P0的`trusted_machines.csv`里`verdict`以`usable`开头的流得到：TBM5、TBM6、TBM8、TBM9、TBM10。TBM1到TBM4缺扭矩或活动行极少，不分段 |
| 连续掘进段 + 阶段划分 | 段表`segments.csv`和逐行标签`labels/<机器>.parquet`（段号、阶段码、运行状态），阶段是上升、稳定、下降三段 |
| 人工抽样验证 | [review/](segments_v1/review/)：抽样表、每段一页的图、答题说明、评分脚本；工程师填完后用`p2_review_score.py`算比例 |

**不在默认里、看图后加的三项（请确认，Q10到Q12）：** ①状态为开而推力连续为0达120秒的行不算掘进，切出段外；②阶段只由推力和推进速度判定，扭矩只要求为正；③停滞段（状态为开、推力在、推进几乎为0）加`stalled`标记，不改分段。

## 二、规则与参数

所有参数在`p2_segment.py`开头的`PARAMS`，写入[manifest.json](segments_v1/manifest.json)，改参数后重建即可。

| 参数 | 值 | 含义和理由 |
| --- | --- | --- |
| `max_gap_s` | 60秒 | 相邻读数间隔超过它就断开。与旧基线的窗口规则一致。第三节给出放宽到120秒的代价 |
| `interrupt_s` | 120秒 | 状态为开而推力不大于0的连续时间达到它，这些行不算掘进。更短的推力掉零（几十秒）留在段内 |
| `blip_s`、`long_s` | 60秒、300秒 | 不足60秒或没有一行活动的是瞬时段；300秒起是长段，才划阶段。长段占段时间的96.7% |
| `rho_F`、`rho_v`、`rho_T` | 0.9、0.8、0（只要求为正） | 平滑后的推力、推进速度分别达到本段稳定水平的90%、80%，才算进入稳定段。阈值是常规的“接近平台”，没有朝某个目标调。第五节给出换阈值的后果 |
| `hold_rows`、`smooth_rows` | 3、5 | 达到要保持3个读数；信号先取5个读数的滚动中位数 |
| `steady_from`、`steady_to` | 0.25、0.75 | 本段的稳定水平取段中间一半（按行）的中位数 |
| `trail_s` | 300秒 | 下降段从“推力或推进速度相对此前5分钟的水平降到90%或80%以下”开始，不对照整段水平，免得缓慢漂移被当成下降 |
| `end_max_s` | 300秒 | 段末低于水平的时间超过它是漂移或水平变化，不叫下降段（该段末尾码为4） |
| `valid_min` | 0.9 | 段内`valid_core`行不足90%不划阶段（v无效的文件落在这里） |
| `stall_v` | 2 mm/min | 段内全部有效行的推进速度中位数低于它，标记`stalled` |
| `n_rotating` | 0.5 rpm | 段外的行：转速不低于它是`rotating`（刀盘在转而不掘进），低于它是`stopped`，转速缺失是`unknown` |

**边缘类型**（`left_edge`、`right_edge`）：`state_change`（状态变化，下一个读数间隔不超过60秒）、`pause`（推力为0的停顿被切掉）、`hole_boring`（读数缺口，缺口另一侧仍是掘进行，这个边缘肯定被截断）、`hole_other`（缺口另一侧不是掘进行，真实的起止点可能在缺口里）、`series_edge`（机器数据的第一行或最后一行）。`censored`指不是前两种。上升段只在左边缘为`state_change`、`pause`、`hole_other`时命名，下降段对右边缘同理，其余留作未命名（码4），因为那里看不到状态变化本身。

**码**（[label_dictionary.csv](segments_v1/label_dictionary.csv)）：`seg_no`为段号（−1是段外）；`phase`为0段外、1上升、2稳定、3下降、4段内但没有命名阶段（瞬时段、短段、无稳定水平、有效行不足、被洞遮住的边缘、超过5分钟的末端低水平）；`op_state`为0掘进（段内）、1刀盘在转而不掘进、2刀盘不转、3转速缺失。段表的每一列见[segment_dictionary.csv](segments_v1/segment_dictionary.csv)。

## 五、阶段划分

### 5.1 定义

稳定水平取段中间一半的中位数。**稳定段**从推力和推进速度（平滑后）第一次同时达到稳定水平的90%和80%并保持3个读数开始，到它们相对此前5分钟的水平不再同时达到为止；**上升段**是稳定段之前，**下降段**是稳定段之后（不超过5分钟）。稳定段内部允许有短暂的凹陷（`steady_ok_share`记录稳定段里有多少行达到整段水平，TBM5、TBM6有31%和43%的长段低于0.9，TBM8、TBM9、TBM10为5%到8%）。

### 5.4 看图发现的几种情形（这些情形留在数据里，没有修）

- **水平变化**：段内先在较低水平稳定，后来整体抬高，前一段被标成上升段（抽样里R035：推进速度约20 mm/min稳定到第7分钟后升到约28；R085：先约35，第7到9分钟升到约50）。这是联合判据的代价；只看推力能避免它，但会把推进为0的低咬合期标成稳定段。
- **K1型状态早于推力**：抽样里R033早了1.4分钟，R062的前6分钟状态为开而推力只有3.5千、推进为0。
- **K1型的周期性凹陷**：TBM6长段里常见每约10分钟一次、约1分钟的推力减半和推进降到近0（抽样的15个TBM6长段中至少3个：R004、R062、R095），留在稳定段内。
- **段内长停滞**：R092在36分钟的段里有两次约2分钟的推进为0（推力在），因为推力不为0所以没有被120秒规则切开。

### 7.3 自查的局限（请照这个读上面的比例）

- 我是规则的设计者，也是打分的人。打分用的标准（约1分钟、什么算“掘进”）是我定的，“不清楚”收了我拿不准的一部分。
- **规则是边看边改的**，最终的98页是改定后才抽的，但此前在较早的规则下我已看过近百页相似的图。看图后改了四处：①加推力为0的120秒规则（先看到一个TBM5段里间隔6分钟推力为0、一个TBM6段尾有18分钟推力为0）；②扭矩退出阶段判据（扭矩单独下降会触发下降段，扭矩阶跃会把前面稳定的一段标成上升段）；③下降段改为对照此前5分钟、加5分钟上限（一个段缓慢降了30%的推力被标出13分钟下降段）；④加`stalled`。所以这98页上的比例是改定后的表现，**不是对新数据的估计**。
- 样本是分层的，抽样层不等比例：完整长段占段数的53%、占段时间的88%，样本里占36%。“全部”一行不是总体的比例。
- 98页只有人眼能判断的现象。看不到的（例如状态标志本身对不对、真正的边界在洞里的什么位置）要靠现场工程师。

## 十、局限

1. **阶段是约定。** 边界对阈值敏感（第5.3节），不同判据的稳定起点可差几分钟；要把标签当作分层变量而不是真值。
2. **段的“真实掘进”未经人工验证。** 自查只覆盖我能从四个信号判断的部分；掘进状态标志的现场含义（Q14）、段是否对应真实的掘进行程（行程约1.8米，许多段不到一整个行程）都没有外部依据。
3. **读数缺口让段碎片化。** 60秒规则下长段里8.5%至少一侧被截断，瞬时段约一半是碎片；`censored`必须跟着数据走。
4. **段内的停滞和凹陷没有切开**：推力不为0的推进为0（R092）、K1型的周期性凹陷留在段内；`stalled`只标记整段几乎没有推进的。
5. **K1型的起止偏差**：状态标志的起止与推力的起止中位相差约30秒，11%到17%的长段在起点或终点超过1分钟。
6. **计数器**只能在TBM5、TBM8上逐段对照；TBM9的导向盾首里程在2024年4到5月交替取两个相差14米的值，未处理（Q15）。
7. 没有对P0的Q1到Q9的新证据；沿用P1的处理。
