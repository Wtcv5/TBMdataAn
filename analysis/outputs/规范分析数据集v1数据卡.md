# 规范分析数据集 v1 数据卡

路线图第四步：建立全运行与连续掘进两种数据视图。输入是[标准时序数据v1](标准时序数据v1数据卡.md)和[P2分段与阶段划分](P2分段与阶段划分报告.md)的段表与逐行标签；处理按P2报告第八、九节写明的默认处理进行（你确认“按默认处理继续”）。数据是每台机器一个parquet文件，在`analysis/outputs/analysis_v1/`；parquet文件由脚本重建（约10秒，逐字节一致，不纳入Git），清单、字典、汇总和校验结果纳入Git。

## 结论先行

1. **规范分析数据集包含5台机器（TBM5、TBM6、TBM8、TBM9、TBM10）、5,566,731行、44列。** 行和行序与v1完全相同，没有删行、插值、平滑或重采样。P2的段号、阶段码、运行状态，三个视图标志，有效行的连续编号`run_id`，以及三个预测步长（30、60、120秒）的窗口目标行与窗口层级，都以列的形式并入。v1里与这次预测无关的8列（位置计数器、驱动电机汇总、`n_raw`、`q_counter_glitch`）留在v1，行序相同，按位置可以拼回。
2. **两种视图是列，不是两份拷贝。** 全运行视图是`valid_core`为真的行：5,512,523行，21,546小时有效观测时间。连续掘进视图是P2“宽口径”段（长段、找到稳定阶段、不停滞）里的行：8,949段、973,749行、3,739小时，占有效行的17.7%，但包含96.2%的有效活动行。严格变体（段的两端都不被截断）8,200段、3,523小时；稳定段变体（阶段码2）847,291行、3,239小时。这些数与P2报告第八节一致。
3. **窗口规则就是已提交基线的规则，并且被逐行复现。** 4个读数的历史、30/60/120秒步长、读数间隔不超过60秒、起点活动、目标是起点后h秒的第一个读数（晚不超过5秒）。用这套规则从旧缓存重建已提交的27个基线数据集（9台机器×3个步长），窗口数、全部特征、目标、起点与目标时间逐项相等。60秒窗口：全运行724,168个，连续掘进673,820个（93.0%），严格642,970个，稳定段587,320个。
4. **两种视图的差别在目标，不在窗口数。** 全运行窗口里3.4%的目标行在掘进段外（刀盘空转或停转），连续掘进窗口里为0。“保持不变”预测的平均绝对误差占目标均值的比例（60秒窗口，各机器按窗口数加权）：推进速度全运行18.7%、连续掘进14.3%、稳定段12.2%；推力8.7%、4.6%、3.2%。所以基线结果必须写明视图，全运行视图里的一部分“难度”来自启停。
5. **窗口的丢失主要来自读数采样，不是数据质量。** 候选起点（有效、活动、前3个读数在同一段连续有效行里）中找到目标的比例：TBM5、TBM6、TBM8（30、60秒）为90%到95%；TBM9、TBM10只有48%到57%，TBM8的120秒窗口只有47%。原因是读数间隔不规则（TBM9、TBM10是10、20、30秒混合，TBM8是10或11秒），起点后恰好h秒处没有读数的起点没有窗口。改用“最近读数±5秒”只对TBM8有效（120秒窗口60,174个变121,990个），对TBM9、TBM10几乎没有帮助（见问题Q16）。
6. **和已提交基线窗口的对账，每一处差别都有解释。** TBM8完全相同；TBM6只少325到540个（窗口里有`valid_core`剔除的行）；TBM5多10万个窗口，因为旧基线把TBM5-2024整条流隔离了（与TBM6-2024、TBM2-2024互为副本，被双方一起隔离），而P0判定它是真实数据；TBM9有约一半窗口的转速特征不同（旧的转速列在119个文件里装的是电机频率，v1按默认处理还原）；TBM9、TBM10多出的几百到一千多个窗口含旧缓存里没有的行（被旧规则整文件隔离的文件的保留部分）。
7. **验证**：182项检查通过（与v1和P2标签逐行对应；视图由段表独立重算；游程编号、窗口目标、窗口层级各用一种不同的方法独立重算；按定义逐行读取检验每台机器每个步长400个抽样起点；汇总表由存储的列重算；逐字节重建）；合成数据自检32项通过，其中植入的窗口与视图情形按手算结果落位，15种篡改（其中10种改动数据文件并同步更新清单）全部被验证脚本发现。

## 四、两种视图

| 视图 | 行的条件 | 窗口的条件 | 在数据里 |
| --- | --- | --- | --- |
| 全运行 | `valid_core`为真 | 窗口的行都是有效行、同一游程（读数间隔不超过60秒）；起点活动；目标在起点后h到h+5秒 | `valid_core`；`win<h>_level`≥1 |
| 连续掘进 | P2段表里`seg_class`为long、`phase_status`为ok、`stalled`为假的段的行 | 窗口的所有行在同一个这样的段内 | `view_boring`；`win<h>_level`≥2 |
| 　严格变体 | 宽口径中两端都不被截断（`left_censored`、`right_censored`都为假）的段 | 同上，起点行与目标行都在严格段内 | `view_strict` |
| 　稳定段变体 | 连续掘进视图中阶段码为2的行 | 窗口的第一个历史行和目标行都在同一个段的稳定阶段 | `view_steady`；`win<h>_level`=3 |

窗口层级是嵌套的：0没有窗口，1全运行，2也在连续掘进视图，3也在稳定段视图；严格变体用`view_strict`再取。

活动行几乎全在掘进段内：TBM5、TBM6、TBM8没有一个活动行在段外，TBM9、TBM10共102行。所以全运行窗口的起点几乎都在掘进段内（TBM9、TBM10有54个起点在段外），两种视图的窗口集合差别在于窗口的其余行和目标。

## 五、窗口规则

窗口由起点、起点之前的3个读数和起点后h秒的目标读数组成，都是该机器原时间戳上的读数。

1. 窗口里每一行都是`valid_core`的行，相邻两行间隔不超过60秒。游程`run_id`就是这样连续的有效行。
2. 起点的F、T、n、v都大于0（`active`）。
3. 目标是起点之后h秒的第一个读数，最多晚5秒。目标可以是停机后的读数（“未来停机算在内”）。
4. 特征是起点和3个历史读数的F、T、n、v，与起点的差，以及相隔的秒数；目标是目标读数的F、T、v。

与基线的等价性：基线以“坏行（非有限或为负）使本行和下一行断开”实现规则1，写在`build_baselines.py`里；`p3_windows.py`以游程编号实现，坏行的定义换成`valid_core`。`p3_regress.py`用同一套函数从旧缓存重建已提交的27个数据集（准备步骤照搬`prepare()`：隔离文件、去掉无时间的行、去掉冲突和重复时间戳），全部逐项相等；`smoke_test_p3.py`另外在含零、负值、缺失和不规则间隔的合成序列上与基线窗口循环的原样拷贝比较，也相等。

## 十一、使用与限制

1. **视图的名称依赖P2。** 段和阶段都是约定，边界对阈值敏感（P2报告第5.3节），且未经人工验证（Q13）；稳定段视图受阶段边界的影响最大。
2. **窗口数不是样本量。** 60秒窗口以每个读数为起点，相邻窗口的行几乎全部重叠；区间估计要按日或按段分块（第二节给出了天数）。P4划分时同一个段、同一天不能跨训练和测试。
3. **窗口集合由读数采样决定。** TBM9、TBM10约一半、TBM8的120秒约一半的候选起点没有窗口（第六节），留下的是读数格点对得上的那些；机器之间的窗口数不可直接比较。
4. **全运行视图仍要求起点活动。** 停机起点、开机预测不在窗口里（Q17）；全运行视图的“全”指窗口可以经过启停，不是起点包含所有状态。
5. **`valid_core`比旧基线严。** 同样的窗口规则，行有效性的判据不同，窗口数略少（已提交窗口里因此消失的：TBM5 1.7千到3.0千，TBM6 325到540个，TBM9 1.9千到2.8千，TBM10 2.1千到2.7千）。
6. **TBM9的转速。** 约一半窗口含按v/p还原的读数；`n_source`在分析数据集里，可以只取导出值做敏感性（P5）。
7. **位置、里程、环数没有进分析数据集**，TBM9的里程交替问题（Q15）仍未解决。
8. **没有切分。** 本步骤不划分训练、验证、测试；`origin_days`、`run_id`、`seg_no`是P4划分要用的分块键。
